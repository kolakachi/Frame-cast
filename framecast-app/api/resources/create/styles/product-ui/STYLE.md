# Product UI build

The product is the hero. Its real interface assembles on screen, piece by piece, as the voice names each feature, so the viewer sees the product being used, not described.

## Look
- One calm background field (brand dark or light), with a soft vignette or a faint grid. The UI is the brightest thing on screen.
- Rebuild 2 to 4 of the brand's real screens as HTML (from the page capture or supplied screenshots): windows, cards, inputs, chips, toggles, a preview. Keep real proportions, radii and spacing.
- The brand accent marks only the active element: the button being pressed, the field being filled, the card that just landed.
- Type: the brand's UI font or Inter for interface text; one display face for the headline line above or beside the UI.

## Motion
- One continuous surface: the UI grows, splits, docks and reflows rather than cutting to new screens. A window can scale down into a card, a card can expand into a panel.
- A cursor or a highlight ring drives each change: it moves, the element responds (press, fill, toggle), and the result lands on the spoken word.
- Real interactions: typing into a field, a toggle switching, a progress bar filling, a card snapping into a grid, a preview starting to play.
- Camera: gentle pushes into the active area and pulls back to show the whole; never a static full-screen UI for more than 2 s.

## Structure
1. Hook: the empty or broken state, or the result first, in the first 2 s.
2. Build: each feature beat adds or changes one part of the UI, timed to its words.
3. Payoff: the finished UI or the output it made, held.
4. Close: pull back to the product name and call to action.

## Never
- Invented numbers, prices, user counts or reviews inside the UI. Use neutral placeholders ("Your product", "Your idea") when there are no approved facts.
- A grid of static cards that only gains one tile per beat.
- Generic stock icons standing in for the real product.
